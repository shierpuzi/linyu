# 倒计时通知修复 · 实测记录

> 2026-10-24 10:07~10:18，RMX3888 / Android 16 / ColorOS，ADB 实测

## 用户报的三个问题

1. **倒计时变成负数也不结束通知**
2. **胶囊（流体云显示实时状态）显示 3:00，不跟着倒计时**
3. （隐含）通知一直挂着不消失

## 根因

### 问题 1+3：`setOngoing(true)` 的通知系统永远不自己撤

- `Chronometer` 过了 `when` 之后**继续往下数**，显示成 `-00:17`
- `setOngoing(true)` 让系统**不会自动撤**，必须 App 自己撤
- 而撤通知的责任在 `viewModelScope` 的 ticker 里 —— **App 退到后台/被杀就没人撤**

实测证据（10:08 抓的）：
```
when = 1792806630207 → 2026-10-24 09:50:30
现在 = 2026-10-24 10:08:20
差值 = -1070 秒（已过期 17 分钟，通知还挂着）
日志：10:47:30 通知自检：已发出 id=1006
```

### 问题 2：胶囊不跟着走 = 没人重发通知

- `shortCriticalText`（胶囊文本）是**发通知那一刻写死**的
- 要更新只能重发整条通知
- 测试按钮 `debugProbeModeOrder` **只发一次，不启动任何刷新循环**
- 所以胶囊永远停在 `3:00`

## 修法（三处）

### 1. `Notifier.showModeOrderRunning` 加 `setTimeoutAfter`

```kotlin
val lingerSec = 60
.setTimeoutAfter((remainingSec + lingerSec) * 1000L)
```

**为什么用 `setTimeoutAfter` 而不是在 ticker 里 cancel**：
它交给**系统计时**，进程死了照样生效。ticker 活在 `viewModelScope`，App 一退就停。

### 2. 新增 `Notifier.startModeOrderAutoRefresh()`

用 `Handler` 每 30 秒重发一次通知，刷新正文文字和胶囊文本；到点自动撤。

**为什么不用 viewModelScope**：用户点完测试按钮直接退出设置页时，ticker 根本没启动。
Handler 挂在主线程，不依赖界面存活。

### 3. 新增 `Notifier.cancelStaleModeOrder()`

App 启动时检查通知栏里 1006 的 `when`，过期超过 2 分钟直接撤。
对付老版本遗留的通知、用户改系统时间、ROM 清掉系统闹钟等情况。

## ⚠️ 仍未解决 / 待观察

1. **`AppLogger` 里看不到「自刷新」日志** —— 但 `timeout` 确实在变，说明循环在跑。
   怀疑日志被后续大量 HTTP 日志挤出（文件 97KB），或 `AppLogger.i` 在那条路径上有问题。
   **不影响功能**，但如果以后要排查，得先确认日志能落盘。
2. **胶囊里显示的文本到底是不是倒计时** —— 需要人眼看通知栏截图确认。
   `shortCriticalText` 长度是 5（`"02:47"` 正好 5 字符），但没截到图。
3. **`PROMOTED_ONGOING` 标志出现了**，但 ColorOS 到底把它渲染成什么样（胶囊在状态栏？在通知卡片？）
   需要人眼确认。
