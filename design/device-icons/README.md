# 设备图标源文件

这里放**设备类型图标**的 SVG 原图，以及把它们转成 Android vector drawable 的脚本。

## 文件

| 文件 | 说明 |
|---|---|
| `shower.svg` | 热水器 / 淋浴——源图（多色 emoji 风格）|
| `sink.svg` | 洗手台 / 洗漱——源图 |
| `svg2vector.py` | 转换脚本：单色化 + 归一化到 24dp 画布 |

生成物在 `app/src/main/res/drawable/`：

| 源图 | 生成 | 用在 |
|---|---|---|
| `shower.svg` | `ic_device_shower.xml` | 🚿 热水器 |
| `sink.svg` | `ic_device_sink.xml` | 🪥 洗手台 |
| — | `ic_device_*`（暂无）| 🚰 饮水机三种还是 emoji，见下 |

## 怎么重新转

```bash
python design/device-icons/svg2vector.py
```

⚠️ 脚本里的输入输出路径是**写死的绝对路径**，换机器要改 `__main__` 里那两行。

## 为什么是 emoji 图，不是图标

这两张原本是 **emoji 风格的彩色图**（多色 + 细节丰富），不是为 24dp 单色图标设计的。所以脚本要额外做两件事：

1. **合并成单色**——颜色全部丢掉，实际颜色由使用处的 `tint` 决定
2. **砍细节**——花洒原本有 7 条水流线，缩到 14dp 会糊成一片，砍到 3 条

## 转换踩过的坑

改脚本时别踩回去，这些都在代码注释里标了：

| 坑 | 症状 |
|---|---|
| 把所有数字两两配对当坐标算包围盒 | `m`/`l`/`c` 后面是**相对偏移**，圆弧参数里还混着半径和标志位——框会离谱到画布外面 |
| 子路径开头的 `m` 当成绝对坐标 | 它是**相对上一段终点**的。单独解析会当成从原点起算，**砍掉中间几条会让后面全部错位**，必须改成绝对 `M` |
| 正则要求两个数之间有空白/逗号 | `m-26.339-143.517` 里**负号本身就是分隔符**，一漏包围盒就飞了 |
| **圆弧只记端点** | 圆弧会鼓出端点之外 → 框偏小 → 系数算大 → **内容被画布裁掉**（牙刷的刷毛就是这么缺了一截的）|
| 圆弧「两端点各扩一个半径」 | 对短弧太松：花洒那条 `a141.933` 半径 142、弧很短，图标被压小 12% |
| 圆弧取所在椭圆的外接矩形 | 对**短弧 + 大半径**同样太松：刷柄 `a12.282` 半径 12、两端只隔 4，整张图被撑到 34×47 |

**正解**：端点参数 → 中心参数转换，算出弧**真正扫过的角度区间**，只在区间内的 0°/90°/180°/270° 极值点取样。既不漏鼓包，也不虚胖。

## 饮水机那三个还没换

`🚰 / ❄️ / ♨️` 目前仍是 emoji。要换的话：

- 在这个目录放源图，跑脚本生成 `ic_device_water.xml` 之类
- 在 `ui/DeviceGlyph.kt` 的 `deviceIconRes()` 里加两行映射

⚠️ **数据层不用动**——emoji 字符串仍然贯穿 `PrefsHelper.lastDeviceEmoji` 和小组件快照，
换图标只发生在渲染时。这是有意的：直接改 emoji 字面量会让**老用户设备上存着的旧值认不出来**。

> 顺带一提：小组件那边**不换**，账单行和附近设备行的圆头像继续用 emoji。
